#  LectureEngine
### نظام ذكي لمعالجة المحاضرات التعليمية وفهرستها والبحث الدلالي داخل محتواها

---

## 1. نبذة عن المشروع

**LectureEngine** هو نظام ذكي يعتمد على تقنيات الذكاء الاصطناعي ومعالجة الوسائط المتعددة لتحويل المحاضرات المسجلة بالفيديو إلى محتوى تعليمي منظم وقابل للبحث والاسترجاع.

تتمثل الفكرة الأساسية في أن الطالب أو الباحث لا يحتاج إلى مشاهدة المحاضرة كاملة للعثور على معلومة معينة؛ إذ يستطيع النظام تحليل الفيديو واستخراج الشرائح والنصوص والكلام المنطوق، ثم ربط هذه المعلومات ببعضها وفهرستها، بحيث يمكن للمستخدم طرح سؤال باللغة الطبيعية والحصول على إجابة مرتبطة بمحتوى المحاضرة.

يدمج النظام بين الرؤية الحاسوبية، والتعرف الآلي على الكلام، والتعرف الضوئي على الحروف، والنماذج اللغوية، وتقنيات البحث الدلالي.

## 2. المشكلة التي يعالجها المشروع

تحتوي المحاضرات الجامعية المسجلة على كميات كبيرة من المعلومات الموزعة بين:

- الشرائح والعروض التقديمية التي تظهر أثناء المحاضرة.
- الشرح الصوتي الذي يقدمه المحاضر.
- النصوص والمعادلات والمعلومات المكتوبة داخل الشرائح.
- التسلسل الزمني للمحاضرة والعلاقة بين الشرح والمحتوى المعروض.

وتكمن المشكلة في صعوبة الوصول إلى معلومة محددة داخل تسجيل طويل، حيث يضطر الطالب غالباً إلى إعادة مشاهدة أجزاء كبيرة من المحاضرة للوصول إلى الإجابة.

لذلك يقدم LectureEngine حلاً يقوم بتحليل المحاضرة تلقائياً، واستخراج المعلومات منها، وربط النصوص بالزمن والشرائح المناسبة، ثم إتاحتها للبحث والاستفسار.

## 3. أهداف المشروع

1. تحليل المحاضرات المسجلة بالفيديو بصورة آلية.
2. اكتشاف الشرائح التعليمية وتمييزها عن الشاشات الفارغة والانتقالات.
3. استخراج النصوص من الشرائح باستخدام OCR.
4. تحويل الكلام المنطوق إلى نص باستخدام تقنيات التعرف على الصوت.
5. ربط محتوى الشرائح بالشرح الصوتي وفقاً للتوقيت.
6. تحسين النصوص المستخرجة باستخدام النماذج اللغوية.
7. إنشاء فهرس قابل للبحث الدلالي داخل المحاضرات.
8. تمكين المستخدم من طرح الأسئلة باللغة الطبيعية.
9. تقديم إجابات مدعومة بالمعلومات المستخرجة من المحاضرات، مع إظهار المصادر والتوقيتات المرتبطة بها.

## 5. نماذج الذكاء الاصطناعي والتقنيات المستخدمة

### 5.1 نموذج YOLOv8n-cls

يستخدم النظام نموذج YOLOv8n-cls في تصنيف إطارات الفيديو، بهدف التمييز بين ثلاثة أنواع من الإطارات:

- `slide`: إطار يحتوي على شريحة تعليمية.
- `blank`: شاشة فارغة أو شبه فارغة.
- `transition`: إطار يمثل انتقالاً بين الشرائح أو المشاهد.

يساعد التصنيف على تحديد الإطارات المهمة وتقليل الإطارات غير المفيدة قبل مرحلة استخراج النصوص.

ويتيح المشروع إعادة تدريب النموذج باستخدام بيانات المحاضرات الخاصة بالمستخدم.

### 5.2 نموذج Whisper

يستخدم Whisper لتحويل الكلام المنطوق داخل المحاضرة إلى نص مكتوب (Automatic Speech Recognition - ASR).

يساعد ذلك على استخراج المعلومات التي يشرحها المحاضر صوتياً، حتى إن لم تكن مكتوبة داخل الشرائح.

ويستخدم المشروع مكتبة `faster-whisper` لتنفيذ عملية التعرف على الكلام بكفاءة.

### 5.3 تقنية PaddleOCR

تستخدم تقنية PaddleOCR لاستخراج النصوص المكتوبة داخل الشرائح والصور المأخوذة من الفيديو.

وتساعد على تحويل محتوى الشرائح إلى نصوص يمكن معالجتها وفهرستها والبحث فيها.

### 5.4 نموذج Qwen

يمكن استخدام نموذج Qwen لتحسين النصوص المستخرجة وفهم السياق وربط المعلومات.

ويُعد استخدامه اختيارياً؛ إذ يستطيع النظام الاستمرار في العمل عند تعطيله، مع الاعتماد على النصوص الخام وآليات الإجابة البديلة.

### 5.5 نموذج التضمين متعدد اللغات

يستخدم النظام نموذج `multilingual-e5-small` لتحويل النصوص إلى تمثيلات رقمية (Embeddings)، مما يتيح البحث عن المعنى وليس مجرد مطابقة الكلمات حرفياً.

### 5.6 قاعدة بيانات ChromaDB

تستخدم ChromaDB لتخزين التمثيلات الرقمية والمعلومات المرتبطة بمحتوى المحاضرات، وتوفير إمكانية البحث الدلالي واسترجاع المقاطع المناسبة عند طرح الأسئلة.

## 6. مراحل معالجة المحاضرة

تمر المحاضرة بمجموعة من المراحل المتتابعة:

**المرحلة الأولى: استقبال المحاضرة**

يمكن إدخال المحاضرة من خلال ملف فيديو أو رابط مدعوم، ثم يبدأ النظام تجهيزها للمعالجة.

**المرحلة الثانية: استخراج الإطارات**

يتم أخذ عينات من الفيديو وفق فترة زمنية محددة، ثم تجهيز الإطارات للتحليل.

**المرحلة الثالثة: تصنيف الإطارات**

يستخدم YOLOv8n-cls لتحديد الإطارات التي تحتوي على شرائح تعليمية، واستبعاد الإطارات الفارغة والانتقالات غير المهمة.

**المرحلة الرابعة: استخراج النصوص من الشرائح**

يتم تمرير الإطارات المناسبة إلى PaddleOCR لاستخراج النصوص المكتوبة باللغة العربية أو الإنجليزية.

**المرحلة الخامسة: استخراج الكلام المنطوق**

يتم استخراج المسار الصوتي من الفيديو، ثم تحويله إلى نص باستخدام Whisper.

**المرحلة السادسة: الدمج الزمني**

يتم ربط النصوص المستخرجة من الشرائح بالكلام المنطوق وفقاً للتوقيتات الزمنية، لتكوين محتوى أكثر ترابطاً.

**المرحلة السابعة: تحسين النصوص**

يمكن استخدام Qwen لمراجعة النصوص وتحسين ترابطها وسياقها، مع الحرص على عدم تغيير المعنى الأصلي للمعلومات.

**المرحلة الثامنة: الفهرسة والتخزين**

يتم تجهيز المحتوى وتحويله إلى تمثيلات رقمية، ثم تخزينه في ChromaDB ليصبح قابلاً للبحث والاسترجاع.

**المرحلة التاسعة: الأسئلة والأجوبة**

عندما يطرح المستخدم سؤالاً، يبحث النظام عن المقاطع الأكثر ارتباطاً بالسؤال، ثم ينشئ الإجابة بالاعتماد على المعلومات المسترجعة.

## 9. تثبيت المشروع على Windows

### الخطوة الأولى: تنزيل المشروع

افتح Git Bash أو موجه الأوامر، ونفّذ:

```bash
git clone https://github.com/tahafoud/LectureEngine.git
```

ثم انتقل إلى مجلد المشروع:

```bash
cd LectureEngine
```

### الخطوة الثانية: إنشاء بيئة افتراضية

```bash
python -m venv .venv
```

### الخطوة الثالثة: تفعيل البيئة الافتراضية

في Windows باستخدام PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

أو باستخدام Command Prompt:

```cmd
.venv\Scripts\activate.bat
```

### الخطوة الرابعة: تحديث pip

```bash
python -m pip install --upgrade pip
```

### الخطوة الخامسة: تثبيت المكتبات

```bash
pip install -r requirements.txt
```

### الخطوة السادسة: إعداد ملف البيئة

أنشئ نسخة من ملف الإعدادات:

```cmd
copy .env.example .env
```

بعد ذلك افتح ملف `.env` وعدّل الإعدادات حسب بيئة التشغيل لديك.

> ملاحظة: لا ترفع ملف `.env` إلى GitHub لأنه قد يحتوي على مفاتيح API أو بيانات خاصة.

## 10. تدريب نموذج تصنيف الشرائح

يوفر المشروع ملفات مستقلة لتجهيز البيانات وتدريب نموذج YOLOv8n-cls.

### 10.1 تجهيز البيانات

يتم استخراج إطارات من الفيديوهات، ثم إزالة الإطارات المتكررة وتجهيزها للتصنيف والمراجعة.

### 10.2 تصنيف البيانات

يتم تنظيم الصور ضمن الفئات التالية:

```text
data/
│
├── videos/
│
└── manual/
    ├── slide/
    ├── blank/
    └── transition/
```

يمكن مراجعة الصور الناتجة وتصحيح التصنيفات قبل بدء التدريب.

### 10.3 تقسيم البيانات

يتم تقسيم البيانات إلى:

- 80% للتدريب.
- 10% للتحقق.
- 10% للاختبار.

يراعي المشروع تقسيم البيانات بحسب الفيديو عند توفر عدد مناسب من الفيديوهات، للحد من تسرب الإطارات المتشابهة بين مجموعات التدريب والاختبار.

### 10.4 تشغيل التدريب على Windows

بعد تجهيز البيانات، يمكن تشغيل التدريب بالأمر التالي:

```bash
python training/run_training.py --videos data/videos --manual data/manual --out .
```

ويمكن تنفيذ مراحل التجهيز والتدريب بشكل منفصل وفق الخيارات المتاحة في ملف التدريب.

### 10.5 التدريب باستخدام Google Colab

يوفر المشروع دفتر تدريب:

`notebooks/LectureEngine_Colab_Training.ipynb`

يمكن استخدامه لتنفيذ التدريب على Google Colab والاستفادة من وحدة معالجة الرسوميات المتاحة.

ويُفضّل استخدام GPU مثل NVIDIA T4 عند توفره.

من مخرجات التدريب المتوقعة:

- النموذج المدرب `best.pt`.
- تقارير مقاييس الأداء.
- مصفوفة الالتباس (Confusion Matrix).
- ملفات توضح نتائج التدريب والتحقق.

**ملاحظة:** يعتمد التدريب على نموذج YOLOv8n-cls مُدرّب مسبقاً، ثم تتم مواءمته مع بيانات المشروع (Fine-Tuning)، وليس تدريب النموذج من الصفر.

## 12. واجهة API

يعتمد المشروع على FastAPI لتوفير واجهة برمجية يمكن ربطها بتطبيقات أخرى.

تعمل المسارات الأساسية تحت:

`/api/v1`

| الطريقة | المسار | الوظيفة |
|---|---|---|
| POST | `/lectures` | إضافة محاضرة جديدة |
| GET | `/lectures` | عرض المحاضرات |
| GET | `/lectures/{id}/status` | معرفة حالة معالجة المحاضرة |
| GET | `/lectures/{id}/slides` | عرض شرائح المحاضرة |
| DELETE | `/lectures/{id}` | حذف محاضرة |
| POST | `/ask` | طرح سؤال نصي |
| POST | `/ask/voice` | طرح سؤال صوتي |

### مثال على إرسال سؤال

```json
{
  "question": "اشرح مفهوم الذاكرة الافتراضية",
  "lecture_id": "lecture_id",
  "top_k": 5
}
```

يمكن تحديد المحاضرة المراد البحث داخلها، كما يمكن تحديد عدد النتائج المراد استرجاعها.

### حالات الإجابة

يدعم النظام أنماطاً مختلفة للإجابة:

- `llm`: إجابة باستخدام النموذج اللغوي.
- `extractive`: إجابة استخراجية اعتماداً على النصوص المسترجعة.
- `none`: لا تتوفر إجابة مناسبة.

كما يمكن أن تتضمن المصادر معلومات مثل:

- عنوان المحاضرة.
- رقم الشريحة.
- التوقيت داخل الفيديو.
- النص المرتبط بالنتيجة.
- رابط صورة الشريحة.
- درجة ارتباط النتيجة بالسؤال.

## 13. البحث الدلالي ونظام RAG

يعتمد النظام على مفهوم **Retrieval-Augmented Generation (RAG)**، الذي يجمع بين استرجاع المعلومات وتوليد الإجابات.

وتتم العملية كالتالي:

1. يستقبل النظام سؤال المستخدم.
2. يحوّل السؤال إلى تمثيل رقمي.
3. يبحث في فهرس المحاضرات عن المقاطع الأكثر ارتباطاً بالسؤال.
4. يعيد ترتيب النتائج وفق درجة الصلة.
5. يمرر المعلومات المسترجعة إلى آلية الإجابة.
6. ينشئ الإجابة اعتماداً على محتوى المحاضرة.
7. يعرض المصادر والتوقيتات المرتبطة بالمعلومات عند توفرها.

الهدف من هذه الآلية هو جعل الإجابات مرتبطة بالمحتوى الفعلي للمحاضرات، بدلاً من الاعتماد على معلومات عامة غير مرتبطة بالمصدر.

## 14. معالجة الأخطاء والبدائل

يراعي النظام إمكانية تعطل بعض المكونات أو عدم توفرها، ويوفر آليات بديلة في بعض الحالات.

| الحالة | آلية التعامل |
|---|---|
| فشل استخراج النصوص OCR | إمكانية متابعة المعالجة بالاعتماد على الصوت مع تسجيل التحذيرات |
| تعذر تشغيل Whisper على GPU | تجربة إعدادات بديلة أو الانتقال إلى CPU |
| تعذر تشغيل Qwen | استخدام النصوص الخام وآلية الإجابة الاستخراجية |
| عدم توفر النموذج المدرب | استخدام آلية تصنيف بديلة محدودة |
